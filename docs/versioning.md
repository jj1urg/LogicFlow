# バージョン管理・VCS 運用ルール

本ドキュメントは、LogicFlow における独自バージョニング形式 **`vx.y-rz.w`** の運用実験ルールと、Git / **Jujutsu (`jj`)** の運用方針を定めます。

---

## 1. 独自バージョニング形式 (`vx.y-rz.w`)

**`v` = version（外部仕様・機能バージョン `x.y`）** と **`r` = revision（内部実装・品質リビジョン `z.w`）** の 4 桁で状態を表現します。

| 部 / 桁           | 意味                        | 繰り上げの目安                                                                     |
| ----------------- | --------------------------- | ---------------------------------------------------------------------------------- |
| `v` (`x.y`) — `x` | 破壊的変更 (`1` 以上で適用) | `0` は初期開発フェーズ。`1` 以上で保存形式・API・操作体系の破壊的変更時に加算      |
| `v` (`x.y`) — `y` | 機能追加 (Feature)          | 新規コンポーネント・UI/UX 機能・HDL 連携・エクスポート機能などの追加時に加算       |
| `r` (`z.w`) — `z` | 内部ロジック刷新・修正      | エンジン最適化・アルゴリズム刷新・ツールチェーン移行・バグ修正・テスト拡充時に加算 |
| `r` (`z.w`) — `w` | 非ロジック更新              | フォーマット整形・スタイル微調整・ドキュメント／管理ルール更新など挙動不変時に加算 |

### 繰り上げルール

- 上位の桁が上がった場合、下位の桁はすべて `0` にリセットします。
  - 例: `v0.14-r0.1` → バグ修正 → `v0.14-r1.0`
  - 例: `v0.14-r1.0` → 新機能追加 → `v0.15-r0.0`
  - 例: `v0.15-r0.0` → ドキュメント整備 → `v0.15-r0.1`

---

## 2. `package.json` と SemVer との整合方針

`vx.y-rz.w` を内部と外部で別々の番号体系に分離せず、**`vx.y-rz.w` を単一の正（Single Source of Truth）** として運用し、`package.json` には SemVer 2.0.0 互換表記を同期させます。

| 対象                                                            | 表記形式                                 | 例                             |
| --------------------------------------------------------------- | ---------------------------------------- | ------------------------------ |
| [`CHANGELOG.md`](../CHANGELOG.md) / ドキュメント / コミット説明 | `vx.y-rz.w`                              | `v0.18-r6.0`                   |
| [`package.json`](../package.json) (`version`)                   | `x.y.0-rz.w`                             | `0.18.0-r6.0`                  |
| `main` ship 時のリリースタグ（初回）                            | `vx.y.0`（内部の `vx.y` をそのまま使用） | `v0.18.0`                      |
| `main` ship 時のリリースタグ（同一 `vx.y` の追加バグ修正 ship） | `vx.y.z`（内部リビジョン `z` を使用）    | `v0.18.7`（`v0.18-r7.0` 相当） |

### `main` ship 時の Git タグ運用ルール

- **`vx.y` の初回 ship**: 内部バージョン `vx.y-rz.w` の `vx.y` をそのまま使い **`vx.y.0`** タグを打ちます（例: `v0.18-r6.0` を `main` に ship したら `v0.18.0`）。
  - `develop` 上で複数の `y` を進めてからまとめて `main` へ ship した場合、未出荷の `y`（例: `v0.17.0`）がスキップされて `v0.16.0` → `v0.18.0` と飛ぶのは正常な運用とし、タグ専用の別カウントは行いません。
- **同一 `vx.y` での追加バグ修正 ship（ホットフィックス）**: すでに `vx.y.0` タグが存在する状態で、新機能なし（`y` 据え置き）の修正を `main` へ追加 ship する場合は、内部リビジョン `z` をパッチ桁に入れた **`vx.y.z`** タグを打ちます（例: `v0.18-r7.0` → `v0.18.7`）。これにより Git タグ・アプリ表示・`CHANGELOG.md`・`package.json` の対応が常に 1 対 1 で保たれます。

- `x.y.0-rz.w` は SemVer 2.0.0 のプレリリース表記として妥当なため、npm / Vite+ 等のツールチェーンと衝突しません。
- 実験の観点として、「外部仕様の変化 (`v`) と内部改善 (`r`) を分離して追えること」「開発中リビジョンとリリース節目の対応が破綻しないこと」を継続検証します。

## 3. 更新タイミングと Jujutsu (`jj`) 運用

- **VCS 構成**: 本リポジトリは `.git` と `.jj` を共存させる colocated リポジトリです。
  - `develop`: 通常の開発作業ライン（`jj` 上では bookmark として管理）
  - `main`: 安定したリリースライン
  - **`jj` bookmark の追従について**: `jj` ではコミット／`jj describe`／`jj new` を行っても bookmark（Git のブランチ相当）は自動では前進しません（Git 側からは detached HEAD に見えます）。作業中はそのまま進めて問題なく、区切りや push 前に `jj bookmark set develop -r @`（`jj new` 後なら `-r @-`）で明示的に追従させます。
- **バージョン更新の粒度**:
  - 作業途中の細かな `jj` change（`wip` 等の中間スナップショット）ごとに毎回 `package.json` を書き換えるとコンフリクトやノイズが増えるため、**1 つのタスク／修正・機能追加のまとまりが完了したタイミングで `vx.y-rz.w` を繰り上げ、`package.json` と [`CHANGELOG.md`](../CHANGELOG.md) を同時更新**します。
  - 複数の細かい change を整理（`jj squash` 等）してから `develop` / `main` にまとめる運用とも相性が良くなります。

## 4. コミットメッセージ / `jj describe` 規約

### 基本フォーマット

```text
:絵文字: プレフィックス: 要約 (abstract)

必要に応じて詳細を記述
```

### プレフィックス・絵文字と `vx.y-rz.w` の対応

| 絵文字（ショートコード） | プレフィックス | 用途                                               | `vx.y-rz.w` での目安               |
| ------------------------ | -------------- | -------------------------------------------------- | ---------------------------------- |
| 🚧 `:construction:`      | `wip`          | 作業中のとりあえずのコミット・中間スナップショット | バージョン据え置き（完了時に整理） |
| ✨ `:sparkles:`          | `feat`         | 新機能の追加（本番 SemVer の MINOR 相当）          | `y` を加算                         |
| 🐛 `:bug:`               | `fix`          | 既存不具合の修正（本番 SemVer の PATCH 相当）      | `z` を加算                         |
| ♻️ `:recycle:`           | `refactor`     | 内部構造のリファクタリング・最適化                 | `z` を加算                         |
| ✅ `:white_check_mark:`  | `test`         | テストの追加・拡充                                 | `z` を加算                         |
| 📝 `:memo:`              | `docs`         | ドキュメントの作成・編集・修正                     | `w` を加算                         |
| 🔧 `:wrench:`            | `chore`        | 設定ファイル・ビルド・雑用の変更                   | `w` を加算                         |
| 🎨 `:art:`               | `style`        | コードフォーマット・スタイルの微修正               | `w` を加算                         |
| 🚀 `:rocket:`            | `release`      | デプロイ・リリース、`main` ブランチへのマージ      | リリース節目                       |
| 🎉 `:tada:`              | `init`         | Initial Commit のみ                                | —                                  |
